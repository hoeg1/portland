# 将来改造するときのメモ

2026/08/17

旧バージョンが３年放置してわけわかんない状態になったので、どうせまた数年放置する将来を見据え、このバージョンの変更について書き残す。


## 旧バージョンとの違い

- 手役計算やカード表現に BigInt を使わないことにした。
    - 手札はどうせ整数の配列で持つので全カードを 52bit で表現する意味は無い。
    - 代わりに Suit 4bit + Rank 13bit = 17bit でカードを表現した。
- 役の強さについて、単純なランク区別とタイブレークを含む役の強さを分離した。
    - 役の表示がシンプルになった。
- 引数や返却値の意味をなるたけ jsdoc で注釈した。
- 旧バージョンに比べて期待値の計算は力任せのやり方を使った。
    - 計算はさして遅くないので過去の自分と向き合うことを諦めた。
- カードのスートとランクの表現に「縦書き」を使うことにした。
    - ランクとスートを css でバランスよく表示する調整は面倒くさい。
    - 各カードは横並びにし易いよう Span で表現。
    - iPhone で画面表示がうまく行ってなかった問題はたぶん解決できたはず。

## ポーカー役の判定と強さ

ポーカー役は５枚以下の Card 型（中身はただの３２ビット整数）配列 hand を

```js
const poker = new Poker(hand);
```

とすると Poker クラスによって判定される。

関数で十分だが jsdoc の書き方を調べるのが面倒だったので class にした。


このクラスには２つのプロパティがあって、

- poker.type
    - タイブレークを考慮しない役の強さを表す整数。
        - 異なる役ならタイブレークによらず強い役のほうが強い。
        - 各種 type は poker.js の class Poker 以下に static 変数で定義。
            - めんどくせえから freeze はしてない。
- poker.power
    - タイブレークを考慮した具体的な役の強さを表す整数。
        - 同じ type=役 でもこの得点が多いほうが強い。
        - 異なる役同士では文字通り桁が違う点数になるようにしている
        - この点数の範囲はある程度検証しているので、雑に足し合わせた程度では INT_MAX を超えない
    - ストレートではAの価値が変わる等、思いつくバグは取ったがヘンな結果が出たら修正が必要かも

### 分配について

ＣＰＵは各ラウンドについて「この枚数まで引いてよい」リストを個性として持つ。Google翻訳が出してきた draw_limit は長いので dl と略す。

各ＣＰＵが引いて良い枚数は this.get_dl(round) で得られるし、各ＣＰＵの「個性」は、この値が余ったときの分配規則も持っている。


- まだリストに余裕があるのにパスした場合は bunpai の値に応じてリストの後の要素に引く権利を分配する。
    - bunpai = AllNext なら あまりを次のラウンドに加算する。
    - bunpai = 1~x なら あまりを最終ラウンドから前ラウンドに１ずつ分配し続ける。
- 交換を選んだら、交換するたび上限をひとつ減らす。


上記の動作をさせるため、.choice_pass(round) と .choice_change(round) がある。

- パスや交換を選んだときに以下のようにすると bunpai について自動で処理される。
    - パスしたいなら: `return this.choice_pass(round);`
    - 交換したいなら: `return this.choice_change(round);`


交換することにした場合、続いて `on_think_change(card)` が呼ばれる。

ここで `card` は個人の山札をめくって出てきたカードを表す整数で、このカードを手札のどのインデックスと交換するかを返す。

画面表示周りではカードを交換したあと発火する関数で画面を更新することが期待される。

- パスはパーキング（🅿）
- 手番は三角形（▶）

として名前の前に状態をつけたりした。

なお、現在の役は CPU or 人間 が共通して継承している Player クラスが .yaku という文字列を持つ。

Player は、さらに history という「追加された得点の履歴」を持ち、katen プロパティから最後の加点を得ることができる。

history に記録されている古い加点情報は、今のバージョンでは活用していない。



### その他の補助関数

思考させるための補助としては他に、Lv3 以上なら確実に以下が使える:

- calc_ev(hand, deck) -> Array[実数期待値のリスト]
    - hand, deck は省略可能で、省略したら自身の手札とデッキ。指定したらそのカードに基いて計算。
    - 現在の手札のうち「最も要らない手札のインデックス」に高得点がつく。
        - リストの各値は実数としてのゆらぎを持つが Poker.power の整数と同じ意味。
        - インデックスは、そのインデックスを交換したときの期待値を意味する。
            - 期待値が最も高いインデックスは「捨てるなら最もおすすめのインデックス」といえる。
    - 手札全体の期待値が欲しいとき（交換したら何点になりそうか知りたいとき）はコメントに書いたように `const x = ev_lst.reduce((acc, ev)=>add+ev, 0);` すればよい。
        - 手札全体の期待値は Poker.power とは意味が違うことに注意したい。
    - 旧バージョンに比べて総当りのアホな計算方法を使っているので効率的ではないと思われる。
        - でも旧バージョンを読むのが面倒。

- fcomb(ary[n], r, func) -> void
    - 要素数 n の配列から r 個選ぶすべての組み合わせを func(a[r]) としてコールバック。
        - a は要素数 r 個の配列。中身は選択された ary[x] の値。

- lv2_think_pass
    - 当たり障りのないプレイとして Lv2 の on_think_pass を呼び出す。

- lv2_think_change
    - 当たり障りのないプレイとして Lv2 の on_think_change を呼び出す。
